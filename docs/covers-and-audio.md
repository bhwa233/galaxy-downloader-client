# 封面与音频的追加下载

本文是实施清单，对应 `requirements.md` 第 2.3 节里"封面与音频的追加"那一组标 ⬜ 的条目。目标：封面能落盘、能嵌进媒体文件，已下过的视频能再要一份音频。

## 1. 与现状的差距

"仅音频"在解析结果上已经可用（见 `requirements.md` 的 2.3），缺的是下载之后再要一份音频的路；封面则完全没有落盘能力，`job.thumbnail` 只是一个用来渲染卡片的地址。字幕不受影响：提取与嵌入今天都已可用且可配（`requirements.md` 的 2.3 与 2.7）。

引擎侧三件事已经具备，不需要自己实现：`writethumbnail`（把封面写成文件）、`EmbedThumbnailPP`（把封面嵌进媒体文件，音频与视频同一套）、以及字幕的 `FFmpegEmbedSubtitle` / `FFmpegSubtitlesConvertor`，都在当前依赖的 yt-dlp 2026.08.19 里。

## 2. 需求

全部行为都是配置项，默认值见第 3 节的表。

**音频**，两种形态都要：

1. 解析结果上的"仅音频"勾选框 —— 保留今天的行为，不动
2. 任务右键「下载音频」 —— 对一个已存在的视频任务再建一个音频任务，原任务与原文件不受影响

**封面**，三种形态都要：

1. 随任务自动存 —— 开启后下载视频时顺带把封面存成同名图片（`<文件名>.jpg`）
2. 嵌进视频文件 —— 下载视频后把封面写进视频文件本身，让它成为视频的封面图
3. 任务右键「下载封面」 —— 点了才存一张

## 3. 设计

**封面的三种形态走两条实现。**自动存与嵌入都走引擎：下载时打开 `writethumbnail`，yt-dlp 会把封面写在与媒体同名的位置；嵌入则再加一个 `EmbedThumbnailPP`，与音频嵌封面是同一个后处理器，只在视频与音频合并之后执行。注意 `engine/main.py` 里的 `CaptureFile` 后处理器目前只记录 `info['filepath']` 和字幕的 `filepath`，封面文件同样要记进 `files`，否则客户端不知道它存在——删除任务时不会清理，"打开文件位置"也看不到它；字幕那段已有的写法可以照抄。手动动作则不走引擎：`job.thumbnail` 已经持久化在任务记录里，直接用现有的 HTTP 下载路径取下来即可。这也是手动动作在客户端重启之后仍然可用的原因。

图文作品（`kind === 'image'`）跳过自动存与嵌入：它的"封面"就是作品本身，而图片没有可嵌的封面轨。

**音频追加必须重新解析。**下载地址在 `ParsePlan.sources` 里，那是一份内存状态，客户端重启或解析别的链接之后就没了；任务记录里的 `job.url` 是页面地址，不是可直接下载的媒体地址。所以「下载音频」必然要重新解析一次。

**实现时改了一处：这次重新解析不在点击那一刻做。**新任务直接沿用原任务的 `url` 与 `itemId` 建出来，解析由队列在它真正开始下载时完成——`execute()` 本来每个任务都要 `resolve()` 一次，那正是同一次解析。这样代价与失败都落在那个任务自己身上：解析失败就是该任务失败，错误信息是解析失败的原因，用户能看到、能重试，而不是点完弹一个跟任何任务都对不上的报错。内容可能已与当初下载的不同这一点不变。

**任务去重键要改。**`queue.ts` 的 `pending(url, itemId)` 用"地址 + 条目"判断是否已有任务在排队，命中就跳过。对一个正在下载的视频任务点「下载音频」会被它挡掉——两者地址与条目都相同，区别只在 `audioOnly`。去重键要把 `audioOnly` 算进去。文件名不会撞：`stemOf(job)` 里带了任务 id 的前八位。

**新增设置项**，放在「文件与媒体」页，与 `organizeByPlatform` 同组：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `saveThumbnail` | `false` | 下载视频时顺带保存封面图片 |
| `embedThumbnailInVideo` | `false` | 下载视频时把封面嵌进视频文件，成为视频的封面图 |
| `embedThumbnailInAudio` | `true` | 仅音频下载时把封面嵌进音频文件 |
| `thumbnailFormat` | 原始 | 封面保存格式：原始格式 / 统一转 jpg |

前两项默认关，因为它们都会改变产出的文件本身或让每个任务多出一个文件，是用户没要求过的行为改变；而手动动作随时可用。

## 4. 已定与待实测

2026-09-22 定下三条：

1. **仅音频默认嵌封面**：默认开。代价是老用户下一次下载得到的文件与上次不同，这一点已接受。
2. **封面保存格式**：默认存**原始格式**（平台给的多是 webp），另加一个设置项 `thumbnailFormat`，用户可以改成统一转 jpg——Windows 资源管理器对 webp 缩略图支持不一致，所以要留这个开关。
3. **手动下封面不受任务状态限制**：任务没下完也允许，与「复制链接」一致。

还有一条仍需实测：

4. **视频嵌封面在 mp4 与 mkv 上的实际表现**。两种容器都支持封面轨，但部分播放器不读 mp4 的封面轨，Windows 资源管理器的缩略图也不一定跟着变。先按引擎默认行为做，拿几个播放器实测之后再决定要不要提示用户。
